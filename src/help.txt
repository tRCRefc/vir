vir - basic ex editor and visual frontend

Usage:
  vir --ex [file ...]   Edit UTF-8/LF files; missing files start empty
  vir --vi [file]      Open a file in a terminal
  vir --help           Show this help
  vir -h               Show this help

Commands are entered without a leading colon. A ':' prompt appears only
when stdin and stdout are terminals; piped sessions have no prompt.

  [range]p / nu         Print lines / print with line numbers
  [address]a / i       Append after / insert before the addressed line
  [range]c / d         Change / delete lines
  u                    Toggle the most recent edit (save preserves undo)
  [range]w [path]       Write all lines or export a range
  [range]wq [path]      Write, then check whether quitting is allowed
  e[!] [path]          Edit another file, or reload the current file
  f [path]             Show status, or change the current file name
  args                 Show the startup file list
  n[!]                 Edit the next startup file
  q / q!               Quit with checks / discard changes and quit
  [range]s/pat/text/[g] Replace first match per line, or all matches with g

Addresses: line number, . (current), $ (last), % (all), /pattern/,
?pattern?, one +/- offset, or comma-separated endpoints. A bare address
prints its range. Empty command prints the next line. 0a inserts at top.
For a/i/c, enter text on subsequent lines; a line containing only '.' ends
input. Empty a/i does nothing; empty c deletes the selected lines.

Example (vir --ex notes.txt):
  a
  hello world
  .
  %s/world/vi/
  w
  q

Patterns use Rust regex syntax, not historical vi BRE. // and ?? reuse
the previous pattern. Replacement text supports &, \1..\9, \&, \\, \/;
$1 is literal. Only '/' substitution delimiters and the 'g' flag work.
File command paths are literal (spaces allowed); no glob/shell expansion.

Behavior and limits:
- Full writes clear the modified flag; partial writes do not. Exporting a
  full buffer to another path clears modified but keeps the current name.
- Partial writes cannot replace the current file. Other existing export
  targets are protected; w! is not implemented.
- q/wq warn once about remaining startup files; a second quit can exit.
- Command errors print '? ...' and continue. Script exit status can still
  be zero. EOF exits without saving, even with unsaved changes; input EOF
  keeps complete input lines but discards an unterminated final input line.
- Saves stage and sync a temporary file before publication. Links and
  unsupported permissions are rejected. ACLs/xattrs are not preserved;
  directory crash durability and external-edit conflict protection are
  not guaranteed. A newly opened missing target cannot overwrite a file
  that appears before its first save.
- No full BRE compatibility, macros, next-with-new-list,
  substitution confirmation, multi-line replacement, or recovery yet.

Legacy: vir <unused-opt> <filename> prints a file without editing it.
This old two-argument entry point is retained; use --ex for editing.

Visual frontend (--vi): requires terminal stdin and stdout. Use hjkl or
arrow keys, 0/$ (Home/End), g/G (first/last line), PageUp/PageDown or
Ctrl-B/Ctrl-F. In normal mode, q or Ctrl-C checks for unsaved changes
before exiting. i inserts before the cursor, a after it, o opens a line
below. A appends at line end, I inserts before the first nonblank (space/
Tab), O opens above. dd deletes lines; counts support 10dd, d10d or
2d3d (six lines). D deletes from the cursor to the end of the line; C
does the same and immediately enters Insert, with deletion and typed text
committed as one undo. Esc/Ctrl-C cancels a pending count/operator. Counts
for other commands except J and other d motions are rejected.
J joins two lines; a count (such as 3J) joins that many lines, clamped at
the last line. Leading spaces/Tabs on following lines are removed. A
space separates text, two after a period, none before a closing parenthesis
or after existing whitespace. The whole join is one undo; final LF is preserved.
Normal r waits for one printable character and replaces the character under
the cursor as one undo; Esc/Ctrl-C cancels it and end-of-line replacement is
rejected.
Normal R enters [REPLACE]: each Unicode scalar overwrites one character,
then appends at line end. Tab replaces one scalar; Enter splits the line.
Backspace restores the previous Replace keystroke, including a split or
append, and stops at session entry. Esc/Ctrl-C commits one undo for the
whole session. Arrow keys and Delete are ignored; R counts are unsupported.
[INSERT] marks text input: Enter splits a line, Tab inserts a tab,
Backspace/Delete remove characters and can join lines. Esc or Ctrl-C
commits the whole input session and returns to normal mode. Arrow keys
are ignored during Insert. Normal x deletes a character; u (or :u)
undoes/restores the last edit, including a whole Insert session.
Type : to enter w [path], q, q!, wq [path], e[!] [path], f [path],
d, u, or s/pattern/replacement/[g]; addresses and ranges follow ex semantics.
Successful edits/loads move to the resulting ex line at column 1.
The status line shows [+] for unsaved changes. Enter executes; Backspace
removes a character; Esc or Ctrl-C cancels command input. Errors appear on the bottom line. Other ex commands
are not supported in visual mode yet. / or ? starts forward/backward
regex search; Enter submits the raw pattern (no closing delimiter or
offset), empty input reuses the last pattern. n repeats, N reverses the
last explicit direction. Searches wrap and move to matching characters;
failed searches preserve the cursor and history. No search highlighting.
Long lines scroll horizontally; Tab stops are 8 columns. Controls display
as caret notation; zero-width characters show a replacement glyph.
Movement uses Unicode scalars, not grapheme clusters; complex emoji and
combining sequences are not fully supported. The last terminal column is
reserved to avoid autowrap. Browsing and searching never change text;
:w/:wq write files. Multiline :a/:i/:c, general counts, dot-repeat, autoindent
and bracketed paste are not implemented. Terminal I/O errors retain the
current Insert draft in memory before returning; no recovery file or
automatic save is provided.
