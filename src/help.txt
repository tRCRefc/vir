vir - basic ex editor and visual frontend

Usage:
  vir --ex [file ...]   Edit UTF-8/LF files; missing files start empty
  vir --vi [file]      Open a file in a terminal
  vir --recover-list [directory]  List recovery snapshots (default: cwd or VIR_RECOVERY_DIR)
  vir --vi --recover SNAPSHOT     Recover text into an unnamed visual buffer
  vir --ex --recover SNAPSHOT     Recover text into an unnamed ex buffer
  vir --help           Show this help
  vir -h               Show this help

Commands are entered without a leading colon. A ':' prompt appears only
when stdin and stdout are terminals; piped sessions have no prompt.

  [range]p / nu         Print lines / print with line numbers
  [address]a / i       Append after / insert before the addressed line
  [range]c / d         Change / delete lines
  u                    Toggle the most recent edit (save preserves undo)
  [range]w [path]       Write all lines or export a range
  [range]wq [path]      Write, then check whether quitting is allowed
  e[!] [path]          Edit another file, or reload the current file
  f [path]             Show status, or change the current file name
  args                 Show the startup file list
  n[!]                 Edit the next startup file
  q / q!               Quit with checks / discard changes and quit
  [range]s/pat/text/[g] Replace first match per line, or all matches with g

Addresses: line number, . (current), $ (last), % (all), /pattern/,
?pattern?, one +/- offset, or comma-separated endpoints. A bare address
prints its range. Empty command prints the next line. 0a inserts at top.
For a/i/c, enter text on subsequent lines; a line containing only '.' ends
input. Empty a/i does nothing; empty c deletes the selected lines.

Example (vir --ex notes.txt):
  a
  hello world
  .
  %s/world/vi/
  w
  q

Patterns use Rust regex syntax, not historical vi BRE. // and ?? reuse
the previous pattern. Replacement text supports &, \1..\9, \&, \\, \/;
$1 is literal. Only '/' substitution delimiters and the 'g' flag work.
File command paths are literal (spaces allowed); no glob/shell expansion.

Behavior and limits:
- Full writes clear the modified flag; partial writes do not. Exporting a
  full buffer to another path clears modified but keeps the current name.
- Partial writes cannot replace the current file. Other existing export
  targets are protected; w! is not implemented.
- q/wq warn once about remaining startup files; a second quit can exit.
- Command errors print '? ...' and continue. Script exit status can still
  be zero. EOF exits without saving, even with unsaved changes; input EOF
  keeps complete input lines but discards an unterminated final input line.
- Saves stage and sync a temporary file before publication. Links and
  unsupported permissions are rejected. ACLs/xattrs are not preserved;
  directory crash durability is not guaranteed. Saves reject changes since
  loading or the last save (content/mtime, plus file identity on Unix),
  including deletion. Conflicts keep edits and wq stays open: reload with
  e! to discard edits, or w NEW_PATH to export them. w! is not implemented.
  A newly opened missing target cannot overwrite a file that appears before
  its first save. The final check and publication still have a race window.
- No full BRE compatibility, macros, next-with-new-list,
  substitution confirmation, or multi-line replacement yet.

Legacy: vir <unused-opt> <filename> prints a file without editing it.
This old two-argument entry point is retained; use --ex for editing.

Visual frontend (--vi): requires terminal stdin and stdout. Use hjkl or
arrow keys, 0/$ (Home/End), g/G (first/last line), PageUp/PageDown or
Ctrl-B/Ctrl-F. In normal mode, q or Ctrl-C checks for unsaved changes
before exiting. i inserts before the cursor, a after it, o opens a line
below. A appends at line end, I inserts before the first nonblank (space/
Tab), O opens above. dd deletes lines; counts support 10dd, d10d or
2d3d (six lines). D deletes from the cursor to the end of the line; C
does the same and immediately enters Insert, with deletion and typed text
committed as one undo. Esc/Ctrl-C cancels a pending count/operator. Counts
for unsupported editing commands are rejected.
Delete motions: dh/dl remove characters left/right; d0 deletes up to the
cursor, d$ through line end. dj/dk delete both current and destination
lines; dG deletes through EOF, d3G through line 3. Counts multiply:
2d3l deletes six characters; d2$ deletes through the next line end.
Arrow keys, Home and End work after d. Horizontal ranges clamp at line
boundaries; out-of-range vertical/G/$ targets fail without changing text.
Each delete is one undo. Word operator motions are described below.
Change motions: ch/cl/cj/ck/c0/c$/cG select the same ranges as d, then
enter Insert. cc changes the current line; 2cc or c2c changes two lines,
and 2c3c changes six. Whole-line changes leave one input line. Deletion
and all typed text form one undo; Esc/Ctrl-C commits even if no text was
typed. A pending c is cancelled by Esc/Ctrl-C. cc and c$ can start input
in an empty buffer. Automatic indentation is not supported.
yy copies lines; yh/yl/yj/yk/y0/y$/yG copy the same ranges as d. Counts
multiply, e.g. 2y3y copies six lines. Copying preserves text and undo.
p/P put the unnamed register after/before the cursor (characters) or
current line (whole lines); 3p repeats the contents in one undo.
Normal d/dd/D/x and c/cc/C also fill this register; changes publish it
when the input session commits. Undo, put and file switches preserve it.
Line puts use LF-terminated lines, even if the original file lacked final
LF. Named/numbered registers, system clipboard and ex yank/put are not
implemented; ex edits and r/R do not update the unnamed register yet.
w/b/e move to the next word start, previous word start, or word end;
counts such as 3w repeat the motion. Words group Unicode letters/numbers
and underscore separately from punctuation; Unicode whitespace separates
words. w/b stop on empty lines, e skips them; whitespace-only lines are
skipped. File boundaries clamp. Combining marks use scalar semantics;
there is no language-specific word segmentation. W/B/E use the same
movement rules but group all consecutive non-whitespace characters,
including punctuation, into a single word. Counts such as 3W are supported.
d/c/y combine with w/b/e/W/B/E; counts before and after the operator
multiply (2d3w selects six words). Forward word deletes/yanks include
following whitespace, but their final segment stops at line end. From
non-whitespace, cw/cW include the current word through its end and leave
trailing whitespace; counts extend through later word ends. From whitespace,
change uses the forward range. e/E include the endpoint; b/B exclude the
original cursor character. Exclusive ranges ending at column 1 leave that
line intact and become linewise if they start within indentation; otherwise
they stop at the preceding line end. Multi-line deletes covering all
nonblank text become linewise; yank/change otherwise remain characterwise.
Word counts clamp at file boundaries. Empty ranges (including forward/end
motions on an empty final line) fail without changing text or registers;
use i/cc/c$ to enter input there. A change plus typed text is one undo;
yanking preserves text, cursor and undo.
Movement counts support w/b/e/W/B/E, hjkl/arrows, $/End, g/G, Home, PageUp/PageDown
and Ctrl-B/Ctrl-F. 2$ reaches the next line end; 5G (or 5g) goes to line 5.
Targets clamp to the buffer; g/G without a count retain first/last behavior.
Home ignores the count; 0 by itself moves to line start, digits such as
10j form one count. Movement never changes text or undo.
J joins two lines; a count (such as 3J) joins that many lines, clamped at
the last line. Leading spaces/Tabs on following lines are removed. A
space separates text, two after a period, none before a closing parenthesis
or after existing whitespace. The whole join is one undo; final LF is preserved.
Normal [count]r waits for one printable character and replaces that many
characters on the current line as one undo (3rX -> XXX, 3r0 -> 000).
The cursor ends on the last replaced character. A short line is rejected
before waiting for input; the count never crosses lines. Esc/Ctrl-C cancels
pending r. Digits supplied after r are replacement text, not another count.
Enter/Tab and quoted control-character replacement are not supported yet.
Normal R enters [REPLACE]: each Unicode scalar overwrites one character,
then appends at line end. Tab replaces one scalar; Enter splits the line.
Backspace restores the previous Replace keystroke, including a split or
append, and stops at session entry. Esc/Ctrl-C commits one undo for the
whole session. Arrow keys and Delete are ignored; R counts are unsupported.
Normal [count]i/a/I/A repeats the net first input segment. The first Enter
consumes the count; later lines are inserted once (historical vi behavior).
3iX<Enter>Y<Esc> inserts XXX then a newline and Y. Counted input is bounded
before accepting each event; an error keeps earlier input and stays in Insert.
o/O accept counts but open input only once: historical vi used these counts
only to reserve screen space on old terminals, not to repeat text.
[INSERT] marks text input: Enter splits a line, Tab inserts a tab,
Backspace/Delete remove characters and can join lines. Esc or Ctrl-C
commits the whole input session and returns to normal mode. Arrow keys
are ignored during Insert. Normal x deletes a character; u (or :u)
undoes/restores the last edit, including a whole Insert session.
. repeats the last successful visual text edit at the current cursor.
It covers Insert/change/Replace sessions, d/dd/D/x, r, J and p/P. 3.
replaces the saved count, rather than multiplying it; a successful counted
repeat keeps that count for the next dot. For changes it replaces the
selection count and types the input once. i/a/I/A repeat only the first
input segment; o/O open and type once even with n. (historical vi). R
currently repeats all input. Each dot is one undo.
Movement, search, yank, undo, saving and ex commands do not replace the
visual repeat record; file switches preserve it. Put repeats use the current
unnamed register. Failed, cancelled or net-unchanged edits preserve the
record. Replay errors leave text, registers, cursor and undo unchanged.
Input replay expansion is limited to 1,000,000 work units (inserted bytes
plus logical input actions and one overhead unit per repetition); larger
counts fail before editing. No terminal escape sequences are replayed.
Type : to enter w [path], q, q!, wq [path], e[!] [path], f [path],
d, u, or s/pattern/replacement/[g]; addresses and ranges follow ex semantics.
Successful edits/loads move to the resulting ex line at column 1.
The status line shows [+] for unsaved changes. Enter executes; Backspace
removes a character; Esc or Ctrl-C cancels command input. Errors appear on the bottom line. Other ex commands
are not supported in visual mode yet. / or ? starts forward/backward
regex search; Enter submits the raw pattern (no closing delimiter or
offset), empty input reuses the last pattern. n repeats, N reverses the
last explicit direction. Searches wrap and move to matching characters;
failed searches preserve the cursor and history. No search highlighting.
Long lines scroll horizontally; Tab stops are 8 columns. Controls display
as caret notation; zero-width characters show a replacement glyph.
Movement uses Unicode scalars, not grapheme clusters; complex emoji and
combining sequences are not fully supported. The last terminal column is
reserved to avoid autowrap. Browsing and searching never change text;
:w/:wq write files. Multiline :a/:i/:c, general counts and autoindent
are not implemented. Terminal I/O errors retain the
current Insert draft in memory before returning. Recovery snapshots are
maintained separately; the original file is written only by save commands.

Bracketed paste (--vi, when supported by the terminal):
- Normal: insert before column 1, otherwise after the cursor, then stay Normal.
  One undo; . appends the same text after the cursor. Registers are unchanged.
- Insert/change: paste into the current input session; Esc commits that entire
  session as one undo. R overwrites characters, splits at LF, and stays Replace;
  actual Backspace restores overwritten characters, including pasted input.
- Text is literal, including Esc/control bytes. CRLF and CR become LF. A Paste
  event is limited to 64 KiB; larger events are rejected without partial edits.
- Pending counts/operators/r are cancelled and the paste is rejected. In : / ?
  input, only one line without control keys (except Tab) is accepted; Enter is
  still required. Pasted newlines never submit a command.
- The mode is disabled on normal exit, terminal errors and unwinding panics.
  Unframed input still acts like typed keys. Terminal framing and upstream
  buffering limits mean this is not a bound on transport memory usage.

Crash recovery:
- CLI sessions checkpoint changed text automatically, including visual input
  drafts before rendering and complete ex input lines before the next read.
- Snapshots are private .vir-recovery-* files beside the initial file. Unnamed
  buffers or missing parent directories use cwd. VIR_RECOVERY_DIR overrides
  this with an existing directory; the directory stays fixed for the session.
- Use --recover-list DIRECTORY to discover candidates, then --vi/--ex --recover
  SNAPSHOT. Restored text is modified and unnamed: w NEW_PATH exports it without
  granting overwrite rights to the original. Undo/registers/cursor are not restored.
- The selected source snapshot stays intact; remove it manually after checking
  the recovered text. Listed snapshots may belong to running sessions.
- Successful full saves/exports, reloads and deliberate normal exits clean this
  session's snapshot. q! and ex EOF deliberately discard unsaved recovery data.
  Errors, panics and process kills retain the last completed checkpoint.
- Recovery I/O failures are shown and do not block editing or saving. Only the
  last successful checkpoint is recoverable; input not yet processed is not.
- Snapshots are limited to 128 MiB, use full-text writes and sync on each change.
  Unix also syncs the recovery directory. This is not a complete power-loss
  guarantee: normal file saves still lack directory fsync. No automatic merge.
